# Audiator — обязательные правила работы

Эти правила применяются **всегда** при работе над проектом Audiator. Порядок действий на каждую
единицу работы: **Jira (В работе) → код + коммиты → комментарий в Jira → PR → Jira (На проверке) →
приёмка пользователем → Готово**.

> **Новая сессия?** Сначала прочитай [`docs/HANDOFF.md`](docs/HANDOFF.md) — там текущее состояние,
> ветки, статусы Jira, открытые вопросы к пользователю и следующий шаг.

---

## Правило №1 — Синхронизация с Jira (главное)

Вся работа привязана к Jira: проект **AUD** — https://t311311311.atlassian.net
(доска: `/jira/software/projects/AUD/boards/2/backlog`).
Ничего «мимо Jira»: каждая **задача**, **дефект** и значимый **комментарий** проходит через Jira.

- **Перед началом работы** — найти соответствующую задачу (или создать) и перевести её в **В работе**.
- **Найден дефект/баг** — завести **Баг** в AUD и связать с родительской историей/эпиком (`parent`).
- **По ходу существенных шагов и решений** — писать **комментарий** к задаче: что сделано, почему,
  ссылки на коммиты/PR. Комментарий обязателен на каждом существенном изменении.
- **По завершении** — перевести в **На проверке** с итоговым комментарием (результат + ссылка на коммит/PR).
  В **Готово** — только после слова пользователя («проверил, работает»).

**Специфика проекта AUD** (team-managed / next-gen):
- Статусы и id переходов: **К выполнению = 11 · В работе = 21 · На проверке = 31 · Готово = 41**.
- Типы задач: **Эпик** (10067) · **История** (10070) · **Баг** (10072).
- Поля **Priority нет** → приоритет и фазу класть в **метки**: `prio-highest|high|medium|low`, `phase-0|1|2`, `commercial`, `e1..e6`.
- Оценка = **Story points** — поле `customfield_10016`.
- Привязка истории/бага к эпику — через поле **`parent`** (ключ эпика).

## Правило №2 — Коммиты в git по мере существенных изменений

- Коммитить на **осмысленных чекпоинтах** — не одним гигантским коммитом и не по мелочи.
  Существенное изменение = завершённый логический кусок (фикс/фича/рефактор), проходящий проверку.
- В сообщении коммита указывать **ключ задачи**: `fix(AUD-9): ...`, `feat(AUD-17): ...`, `fix(AUD-11): ...`.
- **Ветка на задачу** (или группу связанных задач): `feat/aud-33-i18n`, `fix/aud-15-...`;
  изменения оформлять через **PR**; в описании PR — ссылки на `AUD-N`.
- Не смешивать в одной ветке/PR несвязанные задачи.
- Никогда не коммитить: `.env`, `auth-server/audiator.db`, `.venv/`, токены (репозиторий **публичный**).

## Правило №3 — Ручная проверка перед сборкой

- **Не запускать `npm run dist` (сборку установщика), пока пользователь сам не проверил изменения
  руками** через `npm start` и не сказал «собирай».
- Версию в `package.json` поднимать **в момент сборки**, не раньше.
- «Должно работать» — не приёмка. Приёмка — слово пользователя после ручной проверки.

## Что это за приложение

Electron-приложение в трее: запись голоса → транскрибация (faster-whisper) → текст в буфер обмена
→ вставка Ctrl+V; плюс перевод текста. Сейчас это **личный инструмент пользователя**, бэкенд
работает **локально на его ПК** (сервер HOSTKEY не продлён). Коммерциализация — эпики AUD-1…6,
платежи выключены.

### Архитектура

```
Electron (src/)                      auth-server/ (Python, FastAPI)
  index.js        main process   ─►  main.py          :3000  auth + шлюз /asr /translate /languages
  index.html      главное окно         ├─ rate.py            лимиты по IP/устройству (429)
  settings.html   настройки            └─ db.py              SQLite audiator.db: users(role), usage
  activation.html активация      local_whisper.py    :8000  faster-whisper, модель `small`
  recorder-overlay.html  бар     LibreTranslate      :5000  только en↔ru установлены
  i18n.js         словарь en/ru/zh (resolveLanguage: выбор > язык Windows > en)
  local-backend.js автозапуск бэкенда при npm start (не в упакованной сборке)
```

- **Мосты preload** (contextIsolation): `window.api` (preload.js), `window.settingsApi`
  (settings-preload.js), `window.overlay` (overlay-preload.js).
- **Горячая клавиша** Ctrl+Space (globalShortcut) → запись; **оверлей** 96×40 внизу по центру:
  эквалайзер → «Выполняется транскрибация» (красный) → «Готово! Ctrl+V» (зелёный, висит до вставки).
  Вставку ловит `uiohook-napi` (хук клавиатуры включается только пока висит «Готово»).
- **Буфер обмена** пишется через main process (navigator.clipboard требует фокус).
- **Токен**: `device_id.exp.sha256(device_id+SECRET+exp)[:16]`, секрет `AUDIATOR_SECRET_KEY`
  в `auth-server/.env` (без него сервер не стартует).
- **Тарифы**: free — `FREE_DAILY_SECONDS=3600` (60 мин/день, подарок всем); admin — безлимит;
  paid — `PAID_DAILY_SECONDS`. Исчерпан лимит → 402. `PAYMENTS_ENABLED=0` → `/api/auth/subscription`
  отвечает 503, пока нет проверки вебхука оплаты (AUD-15).
- **i18n**: страницы размечены `data-i18n` / `data-i18n-title`, в коде `S('key')` / `tr('key')`;
  главный процесс отдаёт словарь по IPC `get-i18n(lang?)`.

## Как запустить и проверить

```bash
npm start                                              # приложение + сам поднимет бэкенд (:8000/:3000/:5000)
npm run start:test                                     # то же с тестовыми ценами оплаты: месяц 0,10 / год 1,20 USDT
.venv\Scripts\python.exe -m pytest auth-server/tests   # 32 серверных теста
node scripts/check-i18n.js                             # ключи переводов + синтаксис inline-скриптов
.venv\Scripts\python.exe scripts\admin.py list         # аккаунты: list / create "Имя" --role admin / role / use
```

- `scripts/admin.py use <id>` пишет `token.json` + `device.json` в `%APPDATA%\audiator` —
  так приложение входит под нужным аккаунтом (у пользователя — admin, безлимит).
- Ручной запуск бэкенда без приложения: `powershell -ExecutionPolicy Bypass -File scripts\run-local.ps1`.
- Тест оплаты: `npm run start:test` (другие цены — `PRICE_MONTH` / `PRICE_YEAR` перед ним). Сервер, уже
  работающий на 3000, остаётся со своими ценами — команда откажется стартовать; окно оплаты показывает цены
  сервера. Баланс тестового аккаунта: `scripts\admin.py balance <email> [zero | minus 0.02 | reset]` (`reset` — как до оплат:
  баланс 0 и срок снят; `zero`/`minus` срок не трогают), срок отдельно — `paid <email> <дней>`.
- Доп. языки перевода: `.venv\Scripts\python.exe scripts\install-lang.py <code> <code>` (сейчас решено не качать).

## Грабли (выучено на ошибках)

- **Python — только `.venv`.** Глобальный Python общий с другим проектом (Wave/aiogram);
  глобальный `pip install` однажды сломал там pydantic. Никаких пакетов в глобальный Python.
- Код выхода pip проверять у самого pip, не прятать за `| tail` (таймауты сети маскировались под exit 0).
- **Скриншот из панели браузера — это не приложение**: там нет preload, списки пустые. Проверять в `npm start`.
- Настройка шрифта влияет **только на текст транскрипта**, не на кнопки. Ряд кнопок выровнен под
  en/ru/zh (высота 43px, одна строка) — при новых языках прогонять замер ширины/высоты.
- В скрытом окне `requestAnimationFrame` стоит — для индикатора уровня использован `setInterval`
  + `backgroundThrottling:false`.
- Оверлей с `focusable:false` не кликается (WS_EX_NOACTIVATE) — не возвращать.
- Не делать `git rebase` со старыми локальными коммитами поверх чужих правок (однажды затёрло index.js).

## Механика

- **Jira** — через Atlassian MCP (когда подключён) либо REST API `https://t311311311.atlassian.net/rest/api/3`,
  Basic auth (email + API-токен). Токен лежит **вне репозитория**: `%USERPROFILE%\.audiator\jira.cfg`
  (формат curl-конфига: `user = "email:token"`) → `curl -K "%USERPROFILE%\.audiator\jira.cfg" ...`.
  Нет файла — спросить токен у пользователя. **Токен никогда не попадает в репозиторий.**
  - Создание задачи: тело строго `{"fields": {...}}` (без обёртки — 400 на `project`).
  - Описание и комментарии — в формате **ADF** (`{"type":"doc","version":1,"content":[...]}`).
  - Переход: `POST /issue/AUD-N/transitions` с `{"transition":{"id":"21"}}`.
  - Бывают SSL-обрывы — повторять запрос.
- **Git/PR** — ветка → коммиты с ключом `AUD-N` → `git push` → PR. `gh` может быть не авторизован —
  тогда PR открывается по ссылке `https://github.com/t311311311/audiator/pull/new/<branch>`.

## Чек-лист на каждую задачу

- [ ] Задача в Jira существует и переведена в **В работе**
- [ ] Ветка создана, названа по задаче
- [ ] Изменения коммитятся чекпоинтами с ключом `AUD-N` в сообщении
- [ ] Существенные шаги/решения отражены **комментариями** в задаче
- [ ] Найденные дефекты заведены как **Баги** и связаны с родителем
- [ ] Тесты зелёные (`pytest`, `check-i18n.js`), пользователь проверил руками
- [ ] Открыт PR со ссылкой на задачу
- [ ] Задача в **На проверке** с финальным комментарием; **Готово** — после слова пользователя
