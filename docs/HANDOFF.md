## Суть проекта в трёх строках

Трей-приложение на Electron: Ctrl+Space → говоришь → faster-whisper расшифровывает → текст уже
в буфере, «Готово! Ctrl+V» на плавающем баре → вставляешь куда угодно. Плюс перевод текста.
Сейчас это **личный инструмент пользователя**: весь бэкенд крутится **локально** на его ПК
(сервер HOSTKEY не продлён), платежи выключены. Коммерческий план — эпики AUD-1…6 в Jira.

Выбранный путь (2026-09-14): **«пока личный инструмент — дизайн, тесты, закрытие дыры, свежий установщик»**.

## Плавный процент распознавания (ветка `feat/smooth-progress`, 2026-10-05)

Движок сообщает ход только после каждого 30-секундного куска — короткая запись стояла на «0%» и казалась
зависшей. Теперь главный процесс раз в секунду считает оценку: прошедшее время / (длина записи × скорость
этого ПК для этой модели), не больше 95 %, пока текст не готов; настоящий процент движка берётся, когда он
больше; только вперёд; 0 % не показывается; перерисовка только при смене цифры. Скорость (секунд работы на
секунду речи) запоминается по каждой модели (`asrSpeed` в настройках, скользящее среднее, по записям от 5 с);
до первого замера — 0,35 / 0,8 / 2,0 (base / small / large-v3-turbo). На ноутбуке пользователя от батареи
small ≈ 0,7. Нагрузка — одна строка раз в секунду, только пока идёт распознавание.

## История между запусками (ветка `feat/history-keep`, 2026-10-05)

Решение пользователя: история остаётся после закрытия программы. Хранятся тексты и переводы (без звука —
он занял бы гигабайты; сохранить звук можно кнопкой) последних 1000 записей, зашифрованно для пользователя
Windows (`history.dat` в папке данных, DPAPI через `safeStorage`). Пишется через 0,3 с после любого изменения
истории (MutationObserver); «Речь не распознана» и ошибки не хранятся. Стирается при выходе из аккаунта (сам или
по решению сервера) и кнопкой «Очистить историю». Объём: ~1 КБ текста на минуту речи → 1000 записей ≈ 1–5 МБ.
Правила (разделы 2 и 5) обновлены. Время рядом с процентом распознавания убрано — только «Транскрибация… 41%».

## Лимит — это лимит (ветка `fix/limit-stop`, 2026-10-05)

Решение пользователя: бесплатное время закончилось во время записи — запись останавливается сама (смысл лимита —
чтобы покупали), записанное до того распознаётся; без минут запись не начинается («жди обновления»). Окно
приложения сравнивает время записи с остатком: остаток аккаунта минус записи, ещё не засчитанные (сделаны, ждут
текста), — так вторая запись подряд получает только то, что осталось после первой. Остановка: окно всплывает,
«Бесплатное время закончилось — запись остановлена. Записанное распознаётся. Обновление через …», счётчик сразу 0.
Правила (раздел 3) — то же. При открытии окна приложение спрашивает сервер о тарифе (не чаще раза в 30 с).
`scripts/admin.py renew <email> <минут> [--left M]` — тест обновления 24 часов.

## Долгая запись «зависала» (ветка `fix/long-transcription`, 2026-10-04)

Пользователь: при ~3-минутной записи все записи после неё висели на «Транскрибация…». Разбор: не зависание —
движок распознавал медленно (ноутбук от батареи: small ≈ 0,7–1× длины записи, в движке до 2,7× под нагрузкой),

- **Анимации ели процессор**, отнимая его у распознавания: светящийся «Ctrl+V» на баре — 34 % + 30 % ядра
  (GPU + страница), мигающий — 25 % + 13 %; плюс вечный цикл перерисовки бара. Теперь анимации ступенчатые
  (`steps(4)`), цикл — только во время записи: 5–7 % + 7–11 %.
- **Ход распознавания**: движок (`local_whisper.py`) принимает запись как задание — `POST /asr/start`,
  `GET /asr/job?id=` (сделано / длина, сек); приложение спрашивает раз в 0,7 с. В истории: «Транскрибация… 41% ·
  0:35» (время тикает каждую секунду — проценты идут скачками по 30-секундным кускам), следующие — «Ждёт
  очереди…»; на баре бочонок «Транскрибация 45%». Старый `/asr` оставлен (старый движок — без процентов).
- **Скрытая ошибка**: запрос, ждущий весь текст, обрывался бы через 5 минут (так у fetch в Node) — длинная
  запись на медленном ПК упала бы. Задания это снимают.
- `AUDIATOR_ENGINE_PORT` — порт движка в разработке (для тестов рядом с запущенным приложением).

## «Написать нам» и карточка клиента (ветка `feat/support`, 2026-10-04)

- Меню ☰ → «Написать нам» и кнопка в Настройках → «Аккаунт». Окно `support.html`: 4 темы (оплата и баланс,
  ошибка в работе, аккаунт и вход, предложение — решение 2026-10-04: распознавание и перевод — сторонние
  компоненты «как есть», удаления аккаунтов нет, «другое» убрано), текст до 5000 знаков; к письму добавляются
  версия программы, Windows и тариф. Окна «Написать нам» и «Правила», открытые из Настроек, — на языке,
  выбранном там (даже до «Сохранить»); после сохранения нового языка — переходят на него.
- Сервер `auth-server/support.py`, `POST /api/v2/support`: обращение хранится (`support_tickets`) и уходит
  письмом на `SUPPORT_TO` (по умолчанию — ящик отправки, audiatorr@gmail.com). Тема письма:
  `[Оплата] #17 · ivan@mail.ru · бесплатный · ответить до 06.10 14:30 UTC`; в письме — карточка клиента;
  «Ответить» в почте отвечает клиенту (Reply-To). Не больше 5 в час. Письмо не ушло — обращение всё равно
  сохранено (`admin.py tickets` покажет «[письмо не ушло]»).
- Сроки ответа по правилам: оплата — 48 ч; платные — 2 рабочих дня; бесплатные и удаление данных — 5 рабочих
  дней; идеи — без срока.
- `auth-server/clients.py` — карточка клиента: использование за 7/30 дней и всего, активные дни, оплаты,
  компьютеры, обращения; тип: новый (<7 дней) / постоянный (≥15 активных дней из 30) / периодический (4–14) /
  редкий (1–3) / спящий (0). `scripts/admin.py client <email>`, `tickets [--all]`, `ticket <id> answered`.
  Веб-админка с тем же — шаг 6, на сервере.

## Логи сервера (ветка `feat/server-logs`, 2026-10-04)

`auth-server/log_setup.py`, включается переменной `LOG_DIR` (без неё — только консоль, как в разработке).
Новый файл каждую полночь и раньше при `LOG_MAX_FILE_MB` (100); старые сжимаются gzip в фоне (на живом
прогоне 1 МБ → ~60 КБ); удаляются старше `LOG_KEEP_DAYS` (30) и, начиная со старых, когда всё вместе
больше `LOG_MAX_TOTAL_MB` (1024). Наплыв запросов («памп») только укорачивает историю, диск не переполняет.
В логах: время, IP, адрес запроса, статус; предупреждения сервера (логгер `audiator`). Кодов, токенов,
текстов нет, email — только маской. Решение пользователя: IP — персональные данные, храним дни, не месяцы.
Проверено: 6 тестов (размер, полночь, возраст, вчерашний файл при запуске, 8 потоков разом, install) +
живой сервер под 40 000 запросов с лимитами 1 МБ/3 МБ.
